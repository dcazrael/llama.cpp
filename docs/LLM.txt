CURRENT QSA DESIGN
------------------
The old indexer-score-only chunking experiment proved insufficient. Shrinking
that scratch target did not materially change the fatal deep-context workspace.

The active implementation now uses attention-side QSA prefill chunking plus
block-granular selection:
- outer llama ubatch remains unchanged,
- QSA internally uses adaptive 64..256-token query chunks,
- avoids materializing the full [n_kv, ubatch] QSA attention mask for the
  normal single-stream causal path,
- rebuilds causal visibility from cache cell positions,
- ranks compressed blocks before expanding only the selected blocks to cache
  cells; the incomplete causal tail is carried separately,
- avoids the n_kv-wide F32 score expansion and n_kv-wide top-k sort on the
  normal block-bias path,
- still materializes one [n_kv, n_chunk] F16 sparse-attention mask; removing
  that mask/its mask-to-indices rescan is a separate remaining optimization,
- routes both chunked and normal QSA into sparse flash attention when the
  Qwen4Exp MMA sparse shape is supported,
- includes the later future-cell causal-selection correction,
- preserves Generel sampled-decode support.

Relevant design/history:
  docs/decisions/2026-09-17-qsa-indexer-chunking.md

QSA OPTIMIZATION INVARIANTS — DO NOT REGRESS
-----------------------------------------
The active 128K/ub8192 work keeps these three implementation angles together:

1. Native q4_0 K/V in MMA Flash Attention. q4 KV is dequantized per MMA tile;
   do not restore full-cache F16 staging.
2. Block-granular QSA top-k in both normal and chunked paths. Rank compressed
   blocks first, expand only selected blocks, and carry the incomplete causal
   tail separately; do not restore n_kv-wide F32 score expansion/sort on the
   normal causal path.
3. Sparse Flash Attention on the normal QSA path as well as the chunked QSA
   path when the Qwen4Exp MMA sparse shape is supported; do not restore the
   dense KV scan.

The next deeper memory optimization remains removal of the residual
[n_kv, n_chunk] F16 sparse-attention mask / mask-to-indices rescan. That is a
kernel/API change and must preserve per-query causal membership inside a shared
query tile.

LATEST 128K / UB8192 MEMORY EVIDENCE
-----------------------------------
The ISTA GSQ-RCO IQ3_XXS cache48 run on 2026-09-22 processed two 8192-token
prompt chunks at about 484 and 462 tok/s, then failed before the third chunk
while reserving a 5907.82 MiB shared CUDA1 compute workspace.

Important observations:
- the failure is a scheduler workspace reserve, not a kernel allocation,
- the live-KV growth policy was rounding the required ~24576 cells to 32768,
- CUDA1 is the display GPU and was the first device to run out of headroom,
- prefill MoE cache telemetry showed 7675 hits / 13277 misses (36.63% hit rate)
  with 7328 MiB of demand H2D traffic before failure,
- the backend candidate replacement path retires grouped/legacy resources and
  frees their CUDA slot pools when n_slots changes.

Current mitigation:
- live-context KV workspace growth uses a 1024-cell alignment instead of
  power-of-two growth, so 24576 no longer reserves a 32768-cell graph,
- with phase-aware workspace enabled, runtime MoE candidate snapshots are
  capped to 16 slots during prefill,
- the model-configured cache size remains unchanged (48 in the canonical
  suite), and the runtime cap returns to configured size for decode,
- changing phase marks the candidate snapshot and scheduler reservation dirty,
  so backend resources are rebuilt only on the phase transition,
- before a growing live-KV workspace is reallocated, idle CUDA transient-pool
  pages are trimmed after synchronization so the replacement cudaMalloc does
  not compete with retained scratch mappings.

This is deliberately a residency/workspace change. It does not reduce outer
ubatch and must not regress the three QSA optimization invariants above.

BLOCK-FIRST INPUT ALLOCATION GOTCHA
----------------------------------
After block-granular top-k was introduced, the normal block-bias path no longer
consumed the n_kv-wide cell_blk input. Creating it anyway left the tensor with
no backend buffer; set_input_qsa then called ggml_backend_buffer_is_host() on
that null buffer and failed at ggml-backend.cpp:205.

Current invariant:
- cell_blk exists only for the fallback token-level selection path.
- cell_pos exists only when the device-causal chunk path consumes it.
- set_input_qsa must tolerate both pointers being null.
- llama_memory_hybrid_idx_context owns the cache-width lookup via
  get_idx()->get_n_kv() and passes n_kv explicitly to the low-level memory
  object; do not call zero-argument get_n_kv() on llama_kv_cache itself.
- never create graph inputs "just in case": unconsumed inputs may have no
  backend buffer.


NATIVE Q4 FLASH-ATTENTION PATH
------------------------------
The MMA flash-attention path supports direct q4_0 K/V tile loading so q4_0 KV
does not require full-cache F16 staging.

Important plumbing invariant:
- fattn_kernel_t, tile/vec/MMA kernel signatures, and launch_fattn must all carry
  the native-KV mode flag consistently.
- the MMA kernel must propagate q4 mode plus original byte strides through
  flash_attn_ext_f16 -> process_tile -> iter -> load_tile.
- host-side allocation accounting and the MMA launcher must use the same
  need_f16_K / need_f16_V decision.

A partial port previously changed the loader and shared kernel typedef without
propagating those arguments through the MMA call chain. NVCC then failed with
"no instance of function template flash_attn_ext_f16 matches the required
type". It also left the launcher requesting F16 staging even though allocation
accounting had disabled it for native q4_0. Commit b89af7c completes both
halves. Do not reintroduce either mismatch when rebasing FA changes.
